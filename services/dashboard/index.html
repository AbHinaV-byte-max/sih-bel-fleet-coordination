How Decentralized AMR Coordination Works

The architecture that makes zero-collision guaranteed coordination possible

1

Fully Decentralized — No Central Brain

Every AMR runs its own local A* planner and conflict arbiter. No server makes routing decisions. The dashboard only observes — disconnecting it does not affect robot coordination.

2

P2P Intent Sharing → Proactive Conflict Prevention

Each robot broadcasts its intended path (§11.2 space-time reservations) to peers. Others detect potential conflicts before they occur and yield or reroute proactively.

3

§11.1 Deterministic Safety Arbiter — Final Authority

Tie-break hierarchy: Emergency Task → Safety Constraint → Existing Reservation → Task Urgency → Remaining Distance → Robot ID. The Edge AI only adjusts priority weights before the arbiter — it never overrides safety.

4

§14 S1–S10 Scenarios — Validation Taxonomy

Run reproducible test conditions from the Performance view: normal traffic (S1), crossing conflicts (S2), deadlocks (S4), blocked aisles (S5), robot failure (S6), comms degradation (S7), emergency tasks (S8).
